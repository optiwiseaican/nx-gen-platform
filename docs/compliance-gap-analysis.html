What the lab apps already enforce, and what NxGen still has to own

LabApp-WebSocket-M (pH / EC meters) and TLC-Tablet-App (NxGen TLC Scan 10) each built their own compliance layer on the tablet. The master specification moves that layer into the NxGen platform. This page lists every compliance capability in the two apps and shows where NxGen stands on each.

Gap register

What is left to build, by platform layer

A. Compliance core gaps

SMALL
  1. Audit trail export with hash columns, the export itself audited
  2. Editable security policy, changed with reason and signature
  3. Session-expiry warning with an audited extend
  4. Administrator recovery signed by the vendor key
  5. Segregation-of-duties rules and maker-checker role changes
  6. Department, employee ID, designation; scoped permissions
  7. Error, alarm and notification register
Spec §4, §5, §6 · both apps have items 1–4

B. Workflow engine

LARGEST
  • Prepared → Reviewed → Approved, or Rejected back to a chosen stage
  • Stages in order; separate reviewer enforced
  • Records locked once submitted; signed records never deleted
  • Invalidate, then start a new version; the old version stays read-only
Spec §4, §7 · TLC analyses and methods, LabApp reports and calibration

C. Device layer

NOT STARTED
  • Device register: serial, model, Active / Blocked / Retired, probes, maintenance log
  • Calibration: due dates, overdue lockout, versioned acceptance limits, signed approval
  • Diagnostics and readiness checks that gate measurements
  • Secure communication: device identity, TLS, signed and sequenced messages
Spec §9 · Technical Architecture (MQTT / WebSocket)

D. Business layer

NOT STARTED
  • Immutable measurement records; corrections as linked revisions
  • Raw TLC images written once with SHA-256
  • Versioned, approved methods; sample, batch and AR master data
  • Reports with signature manifest and watermarks
  • Controlled document store; encrypted backup and restore
Spec §4, §19

E. Missing in both apps

NEW WORK
  • Trusted time and timezones on every timestamp
  • IQ / OQ / PQ records and the Installation Validation Report
  • SHA-256 software manifest, startup validation, safe mode
  • Encryption of records and backups
  • Lot and expiry tracking, training records, SOP references, periodic audit review
  • Digitally signed PDFs; system suitability tests for TLC; change control

Findings in the apps

Problems to fix or avoid carrying over

  • LabApp diagnostics module deleted. Commit b1d44fe (13 Aug 2026) removed it, yet DIAGNOSTIC_TEST_CASE_COMPLIANCE_AUDIT.md still reports 87 of 87 test cases implemented.
  • TLC hard-deletes unsigned analyses, raw images included. Only the audit entry remains.
  • TLC separate-reviewer rule is off by default, so one person can prepare, review and approve their own work.
  • LabApp EC module has no permission checks and no signatures.
  • LabApp backups are not encrypted, and the mini-PC transfer uses plain TCP.
  • Much work is uncommitted: about 48 files plus new modules in TLC, 33 changes in LabApp.
  • Docs disagree with code in both repositories, for example TLC feature-status.md still lists authentication and audit as not built.
Recommended order

Build sequence

Close the compliance core gaps

Audit export, editable security policy, session warning, administrator recovery. Small, and every later module depends on them.

Workflow engine

Review, approval, locking and versioning, used by measurements, methods, calibrations and reports.

Backup and restore

Encrypted, verified and audited, in place before lab data exists.

Device layer with secure communication

Device register, calibration, readiness checks, authenticated device links.

Measurements and TLC analyses

Bring pH / EC results and TLC plate analyses onto the platform.
